WS4 Guardrails and governance
Bedrock Guardrails policy for the A2Z agent (allowed topics, PII handling, scope limits) plus an orchestrator-level policy on what may be asked at all. A red-team script of roughly ten prompts covering cross-tenant leakage, off-topic requests and PII exfiltration, with pass rate reported. A one-page governance document: who owns policy changes, the approval path, the checklist for onboarding a new agent onto the toolkit, and where the audit log lives.
WS5 Observability monitoring and lineage
OpenTelemetry instrumentation using AgentCore Evaluators. Every invocation carries tenant, persona, agent, model, tokens in and out, latency, cost per answer, guardrail hits, Gateway tool calls, and the retrieval record identifiers used (lineage). One CloudWatch dashboard. Three alarms: error rate, p95 latency, daily spend.
WS6 Evaluation and test harness
A golden dataset of question-and-answer pairs for the A2Z agent (A2Z supplies questions and expected answers; AllCloud builds the harness). A Bedrock Evaluations job scoring accuracy, hallucination and behaviour. The harness is runnable by A2Z with a single command and wired to run on pull requests, and it produces a baseline report. The harness is built so the Phase 2 agents drop in with a new dataset and no code changes.
WS7 Cost and model benchmarking
Cost per answer for the A2Z agent across two or three candidate Bedrock models, using the golden dataset from WS6. Prompt caching enabled on system prompts and static context. A written model-routing recommendation with projected monthly spend at A2Z’s volume projections, which also feeds the AWS funding case.
Cross cutting Infrastructure as code AWS CDK
This requirement applies to every workstream, not only WS1. Guardrails policies (WS4), OpenTelemetry collectors, CloudWatch dashboards and alarms (WS5), the Bedrock Evaluations job and its pipeline (WS6), IAM roles, OAuth2 client registrations and Gateway targets (WS2) are all CDK constructs. Secrets are referenced from Secrets Manager or Parameter Store, never embedded. Console-only configuration is treated as undelivered.
WS8 AgentCore Memory
AgentCore Memory is provisioned and wired into the A2Z agent so the agent remembers within a session and across sessions. Short-term memory captures conversation events per session. Long-term memory uses configured extraction strategies (user preferences and semantic summaries at minimum) with namespaces keyed by tenant and user, so a dealership’s memory can never be retrieved by another dealership. The Strands agent gains memory hooks: retrieve relevant memory before each model call, write events after each turn. Guardrails from WS4 run before anything is persisted so PII policy applies to memory, not only to answers. Retention is configured per namespace and a deletion path exists so a user’s or a dealership’s memory can be purged on request. Memory reads and writes appear in WS5 traces with their cost. All resources are CDK constructs.
