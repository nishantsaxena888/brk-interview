Business Context
Centene Corporation is a Fortune 25 managed care organization serving over 20 million members across Medicaid, Medicare, and ACA Marketplace plans. The company is sunsetting its legacy broker management platform (Novasys Portal) and migrating to Salesforce. The existing system manages policy enrollments, member records, and broker commission payouts, and had accumulated significant tech debt over the years — with business logic embedded in stored procedures and database triggers, making changes to the production codebase high-risk. Nishant supports the ongoing platform transition by maintaining the legacy system and building reconciliation tooling to validate data integrity during the Salesforce migration — ensuring that broker commission data, policy records, and member enrollments are accurately carried over. He also contributes reconciliation tooling for parallel database migration efforts, including Oracle to SQL Server (SSIS packages) and an ongoing Snowflake migration.

Solution Pattern
Delivered enhancements and refactoring on the Django-based Novasys Portal (with FastAPI microservices) while supporting the platform's transition to Salesforce. On the platform side, built Python asyncio Kafka consumers processing Pydantic-validated enrollment events, and engineered an event re-sequencing layer to handle out-of-order Kafka streams — resolving a long-standing issue where misordered events were corrupting policy numbers, enrollment spans, and broker commission data — delivering corrected policy, commission, and enrollment data downstream. Integrated external partner APIs — Softheon Broker Lookup (REST, Pydantic-validated) and OneSource (GraphQL) — to enrich broker and plan metadata for accurate commission calculation. To support the Salesforce migration, built a two-phase Python reconciliation engine that compared 100,000+ policy records between the legacy system and Salesforce, exported structured audit results to AWS S3, used Lambda with SQS dead-letter queues and SNS notifications for downstream validation, and surfaced discrepancy reports to business analysts through a React SPA and Django dashboard. To de-risk releases on a high-tech-debt codebase, built a parallel simulation system to dry-run code changes against 100K+ live policies before each deployment. For parallel database migrations (Oracle to SQL Server via SSIS, and Snowflake), built a DuckDB-powered in-memory reconciliation tool within Django to validate data integrity at scale. All services ran containerized on Rancher-managed Kubernetes, with PII masking, CloudWatch structured logging, and per-service operational alarms — plus a custom RHEL daemon to auto-restart the PgBouncer connection pooler after OS patching.
